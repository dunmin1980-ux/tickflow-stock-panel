# TickFlow Phase 2B Facts-Only AI Review Design

## Status And Authority

This design implements Phase 5 through Phase 10 of the user-approved
`TickFlow Phase 2 AI 个股复盘与 Obsidian 旁路闭环` specification. Phase 2A is already
closed at `PHASE2A_FACTS_READY`; the three committed files in
`reports/phase2_facts/` are the only market-data inputs for this phase.

## Scope

Phase 2B produces one research-material Markdown document for each fixed symbol:

- `000403.SZ` 派林生物
- `600489.SH` 中金黄金
- `300059.SZ` 东方财富

It adds no API endpoint and changes no existing Stock Analysis behavior. It does
not call TickFlow, mutate cloud state, configure an AI key, write to a real
Obsidian vault, publish a financial daily, or start Paper Trading.

## Architecture

`app.services.phase2_ai_review` is a closed offline boundary with five jobs:

1. Validate and hash one committed Facts document.
2. Build a facts-only prompt plus an exact numeric claim catalog.
3. Validate an AI Markdown body before any report is published.
4. Add deterministic YAML frontmatter and revalidate the complete document.
5. Route the complete document to an isolated preview directory.

The historical smoke batch used the already installed Codex CLI once per symbol.
That execution is retained as evidence, but this branch deliberately exposes no
automatic Codex generator: CLI `--sandbox read-only` prevents writes and does not
prove that the child process cannot read unrelated host files. A future provider
runner requires an external container or OS policy that denies host reads before
it can be enabled. The application AI provider remains `openai_compat`; no
application AI setting or key was changed.

## Numeric Claim Contract

The AI does not receive permission to invent, calculate, interpolate, or round
numbers. Deterministic code creates a presentation catalog from the Facts file:

- raw daily OHLC values are rendered with two decimal places;
- qfq price indicators are rendered with four decimal places;
- RSI and volume ratio are rendered with four decimal places;
- minute bar counts are rendered as integers;
- symbol and trade date are exact string claims;
- volume and amount absolute values are withheld because their units are pending;
- key levels are withheld because their deterministic implementation is pending.

Every catalog entry carries its Facts JSON Pointer, Facts SHA-256, basis and unit.
The validator normalizes Unicode and variation selectors, extracts plain,
embedded, Chinese-decimal, percentage, scientific-notation and
thousands-separated numbers, and checks both the literal and its field-specific
context. It permits only section numbers, the fixed symbol/date/timeframe
literals, the exact current Facts hash in its named context, or exact catalog
values used with matching source labels. Each accepted market number is returned
with its source pointer.

This catalog validator is defense in depth, not a complete natural-language
semantic verifier. A freeform body that passes every detector is still rejected
with `freeform_semantic_validation_incomplete`. A future typed Claims contract
must make every assertion machine-owned before `REVIEW_VALID` can be emitted.

## Prompt And Output Contract

The prompt requires exactly these ten headings:

1. 一句话观察结论
2. 日线技术结构
3. 分钟结构
4. 量价变化
5. 关键观察区间
6. 风险边界
7. 下一交易日观察清单
8. 需要人工确认的数据
9. 结论失效条件
10. 免责声明

The body must state in section 8 that market scope is incomplete and that
financial and news data are unavailable and require manual verification. It must
retain all four vendor-pending items in that section. Section 10 contains only
the fixed statement that the material is not investment advice.

The validator rejects transaction instructions, recommendation language,
unsupported numbers, extra symbols, fabricated financial/news claims, missing
sections, missing scope declarations, secrets, HTML/script content, YAML emitted
by the model, or a model-generated title outside the ten-section contract.

## Frontmatter And Routing

Frontmatter is generated by code, never by the model. It fixes:

- `type: stock-daily-review`
- `source_system: tickflow-stock-panel`
- `facts_schema_version: 1`
- `timeframe: [1d, 30m]`
- `data_scope: single-symbol`
- `market_scope: incomplete`
- `financial_scope: unavailable`
- `news_scope: unavailable`
- `verification_status: pending`
- `can_publish: false`
- `trading_advice: false`
- all four vendor-pending entries

Only `REVIEW_VALID` routes to `inbox`. `REVIEW_NEEDS_VERIFICATION` and
`REVIEW_REJECTED` both route to `rejected` as a fail-closed defense. The current
freeform pipeline cannot emit `REVIEW_VALID`, so all three historical samples
remain in `rejected`. No code path writes to `reviewed`.

## Failure And Atomicity

Writes are confined to the repository's exact `reports/` directory. The service
stages the sample and preview trees separately, then publishes each directory
atomically. Cross-directory atomic replacement is not available; an exclusively
created transaction marker serializes publishers and makes crashes fail closed,
and normal publication failures restore both previous trees from backups.
Rejected reviews are preserved only in `rejected`
and make the batch status blocked; they are not silently rewritten.

JSON audit files are opened with no-follow semantics and checked as regular
files before bytes are decoded. This prevents rematerialization from following
a substituted symbolic link.

Provider-attempt counts are process-recorded evidence, not external attestation.
The historical default Codex model name was not captured, so
`codex_cli_default` is an alias and `model_identity_verified` remains false.
Offline rematerialization stores its immediate predecessor audit by SHA-256 and
validates sequence continuity plus immutable provider/body provenance fields;
the two pre-hardening predecessor audits were not retained, so history is
explicitly marked incomplete rather than reconstructed.

## Verification

Focused tests cover prompt restrictions, catalog provenance, Unicode and numeric
bypass shapes, forbidden language, scope declarations, frontmatter, secret
scanning, fixed symbol scope, routing, no `reviewed` writes, write-root
confinement, Setext and HTML bypasses, no-follow audit reads, audit tampering,
transaction markers and rollback behavior. Final
verification also runs the full backend suite, compileall, Ruff F821, output
validators, source-hash checks and a repository secret scan.
